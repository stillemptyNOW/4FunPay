## Что умеет

**Работа с FunPay**

- Автовыдача товаров сразу после оплаты заказа, из товарных файлов или по шаблону.
- Автоподнятие лотов по всем категориям с учётом кулдаунов FunPay.
- Автоответ на заданные команды покупателей.
- Автовосстановление лота после продажи и автодеактивация, когда товар закончился.
- Приветствие новых покупателей с настраиваемым кулдауном.
- Автоответ на отзывы в зависимости от количества звёзд.
- Ответ на подтверждение заказа.
- Постоянный онлайн на аккаунте.
- Поддержка прокси (HTTP/HTTPS/SOCKS5) отдельно для FunPay и для Telegram.

**Telegram**

- Панель управления: все настройки правятся из чата, без доступа к серверу.
- Уведомления о заказах, сообщениях, выдаче товара, поднятии лотов, отзывах.
- Ответ покупателю прямо из Telegram, включая отправку изображений.
- Настройка автовыдачи и автоответчика через меню, лоты подтягиваются с FunPay.
- Загрузка и выгрузка конфигов и товарных файлов файлами в чат.
- Управление доступом: авторизация по паролю, список разрешённых пользователей.
- Несколько чатов для уведомлений с независимыми настройками.

**Аналитика и защита** (штатные плагины, включены из коробки)

- **Монитор цен** — твоя позиция по цене в каждой подкатегории, уведомление о вылете из топа и о том, что тебя подрезали. Видно, у кого из тех, кто ниже, есть автовыдача и кто онлайн. Команда `/prices`.
- **Реальная прибыль** — не оборот, а `цена − комиссия площадки − себестоимость`. Отдельно показывает убыточные лоты. Команды `/profit`, `/setcost`, `/setfee`.
- **Скам-фильтр** — придерживает автовыдачу для подозрительных заказов (крупная сумма, просьба уйти мимо площадки) и спрашивает решение кнопкой. Команды `/guard`, `/held`.
- **Статистика продаж** — сводки за неделю и месяц с графиками, топ лотов, экспорт CSV. Команды `/stats`, `/stats_export`.
- **Заказы по часам** — когда реально приходят покупатели. Команда `/besttime`.
- **Аудит** — компактный журнал действий бота в JSON Lines. Команды `/audit`, `/audit_export`.
- **Watchdog** — уведомление об аварийных перезапусках, heartbeat для healthcheck. Команда `/health`.

**Расширяемость**

- Система плагинов: 18 точек подключения к событиям без правки ядра.
- Переменные в текстах автовыдачи и автоответов (`$username`, `$order_id`, `$product` и др.).
- Интерфейс на русском.

## Требования

| | |
|---|---|
| Python | 3.11 или новее |
| ОС | Ubuntu 22.04 / 24.04, Debian 11+, Windows 10/11 |
| Диск | ~50 МБ |
| ОЗУ | 80–150 МБ |
| Сеть | доступ к `funpay.com` и `api.telegram.org` |

Что понадобится подготовить заранее:

1. **`golden_key`** — cookie сессии FunPay. Залогинься на funpay.com, открой DevTools (`F12`) → **Application** → **Cookies** → `https://funpay.com` → скопируй значение `golden_key`. Это ключ от аккаунта, обращайся с ним как с паролем.
2. **Токен Telegram-бота** — создай бота у [@BotFather](https://t.me/BotFather), получи строку вида `1234567890:AA...`.
3. **Пароль** для входа в панель управления — придумаешь при первичной настройке.

## Быстрый старт: Ubuntu VPS

Пошагово с чистого сервера.

### 1. Подключись и обнови систему

```bash
ssh root@ТВОЙ_IP
apt update && apt upgrade -y
```

### 2. Создай отдельного пользователя

Бот не должен работать от root: у него в конфиге лежит `golden_key`, и лишние права ему не нужны.

```bash
adduser --gecos "" funpay
usermod -aG sudo funpay
su - funpay
```

### 3. Склонируй репозиторий

```bash
git clone {{REPO_URL}} ~/4funpay
cd ~/4funpay
```

### 4. Запусти установщик

```bash
bash install.sh
```

Скрипт поставит Python 3.11+, соберёт venv в `~/pyvenv`, установит зависимости, зарегистрирует systemd-юнит `4funpay@funpay`, запустит мастер первичной настройки и включит автозапуск.

Мастер спросит по порядку: `golden_key` → User-Agent → прокси для Telegram → токен бота → пароль панели → прокси для FunPay. Прокси можно пропускать, нажимая Enter.

### 5. Проверь, что сервис поднялся

```bash
sudo systemctl status 4funpay@funpay
sudo journalctl -u 4funpay@funpay -f
```

В логах должно появиться приветствие с ником аккаунта и балансом.

### 6. Открой панель управления

Напиши своему Telegram-боту пароль, который придумал на шаге 4. Дальше — команда `/menu`.

> Первым делом включи нужные модули: `/menu` → **Глобальные переключатели**. По умолчанию автовыдача, автоответ и автоподнятие **выключены** — это сделано специально, чтобы бот не начал что-то делать с аккаунтом до того, как ты его настроил.

## Быстрый старт: Windows

1. Установи [Python 3.11+](https://www.python.org/downloads/), при установке отметь **Add python.exe to PATH**.
2. Склонируй репозиторий или скачай и распакуй архив.
3. Запусти `Setup.bat` — создаст venv и поставит зависимости.
4. Запусти `Start.bat` — при первом запуске откроется мастер настройки.
5. Запусти `Start.bat` снова и напиши боту пароль в Telegram.

Windows-вариант подходит для проверки и разработки. Для постоянной работы нужен сервер: на выключенном компьютере бот не выдаёт товары.

## Docker

Альтернатива systemd — полезна, если не хочешь ставить Python в систему.

```bash
git clone {{REPO_URL}} ~/4funpay
cd ~/4funpay
cp .env.example .env      # заполнять не обязательно, см. ниже
```

Первый запуск — интерактивный, чтобы пройти мастер настройки:

```bash
docker compose run --rm 4funpay python main.py
```

После того как конфиг создан, поднимай в фоне:

```bash
docker compose up -d
docker compose logs -f
```

Каталоги `configs/`, `storage/`, `logs/` и `plugins/` смонтированы с хоста, поэтому пересборка образа не затирает настройки и товарные файлы.

Обновление:

```bash
git pull
docker compose build
docker compose up -d
```

## Настройка бренда

Всё, что относится к названию и контактам, лежит в одном файле — [`branding.py`](branding.py). Открой его и заполни:

```python
BOT_NAME = "4FunPay"          # название проекта
OWNER_TG = "@твой_username"   # твой Telegram
SUPPORT_CHAT = "@твой_чат"    # чат поддержки
REPO_URL = "https://github.com/твой/репозиторий"
```

Незаполненные значения выглядят как `{{OWNER_TG}}` и в таком виде видны в интерфейсе — это подсказка, что их пора заменить. Кнопки со ссылками, у которых значение не заполнено, просто не отображаются.

Тексты интерфейса ссылаются на бренд через плейсхолдеры (`{{BOT_NAME}}`, `{{SUPPORT_CHAT}}`), которые подставляются в `locales/localizer.py`. Менять три файла локализаций при смене названия не нужно.

Плейсхолдеры также нужно заполнить в:

- `install.sh` — переменная `REPO_URL` (или запускать скрипт из уже склонированного репозитория);
- этом `README.md`.

## Конфигурация

| Файл | Что внутри | В git |
|---|---|---|
| `configs/_main.cfg` | основные настройки, **`golden_key`**, **токен Telegram** | нет |
| `configs/auto_response.cfg` | команды автоответчика | нет |
| `configs/auto_delivery.cfg` | привязка лотов к товарам | нет |
| `storage/products/*.txt` | товарные файлы (ключи, аккаунты) | нет |
| `config.example.ini` | образец основного конфига с комментариями | да |
| `.env.example` | образец переменных окружения | да |

Весь каталог `configs/` и `storage/` закрыт в [`.gitignore`](.gitignore) — секреты в репозиторий не попадут.

### Переменные окружения

Значения из окружения имеют приоритет над файлом конфига. Это удобно для Docker и CI, где не хочется держать секреты в файле:

```bash
FOURFP_GOLDEN_KEY=...        # переопределяет FunPay.golden_key
FOURFP_TELEGRAM_TOKEN=...    # переопределяет Telegram.token
```

Основной способ хранения — всё-таки `configs/_main.cfg`, потому что панель управления в Telegram пишет настройки обратно в этот файл.

### Правка конфига руками

Файлы в формате INI с разделителем `:` вместо `=`. Кодировка обязательно **UTF-8**, перевод строк — **LF**. При ошибке в конфиге бот при старте пишет, в какой секции и какой параметр не так, и завершается — трейсбека не будет.

## Обслуживание

### Логи

```bash
# в реальном времени
sudo journalctl -u 4funpay@funpay -f

# последние 200 строк
sudo journalctl -u 4funpay@funpay -n 200

# только ошибки за сегодня
sudo journalctl -u 4funpay@funpay -p err --since today
```

Плюс собственные файлы бота с полной отладочной информацией: `logs/log.log` (ротация по 20 МБ, 25 файлов). Их же можно забрать из Telegram командой `/logs`.

### Обновление

```bash
sudo systemctl stop 4funpay@funpay
cd ~/4funpay
git pull
~/pyvenv/bin/pip install -U -r requirements.txt
sudo systemctl start 4funpay@funpay
sudo journalctl -u 4funpay@funpay -f
```

Встроенное самообновление из интернета намеренно вырезано: код обновляется только из твоего репозитория, чужой релиз не может перезаписать рабочий каталог. Команда `/update` в Telegram выводит эту же инструкцию.

Перед обновлением сделай бэкап — командой `/create_backup` в Telegram.

### Откат на предыдущую версию

```bash
sudo systemctl stop 4funpay@funpay
cd ~/4funpay

# посмотреть историю
git log --oneline -10

# вернуться на конкретный коммит
git checkout <хеш_коммита>

# либо отменить последний коммит, сохранив историю
git revert HEAD

~/pyvenv/bin/pip install -U -r requirements.txt
sudo systemctl start 4funpay@funpay
```

Если ломается сам конфиг или товарные файлы — восстанови их из бэкапа: `/menu` → **Конфиги** → загрузить `backup.zip`, либо вручную распакуй архив в корень проекта.

Вернуться на актуальную ветку после проверки:

```bash
git checkout master && git pull
```

### Резервные копии

`/create_backup` в Telegram собирает `configs/`, `storage/` и `plugins/` в `backup.zip` и присылает файлом.

> Архив содержит `golden_key`, токен бота и все товарные файлы. Не пересылай его никому и не загружай в облака.

Автоматический бэкап по расписанию — задача для cron:

```bash
crontab -e
```

```
0 4 * * * cd /home/funpay/4funpay && zip -qr "/home/funpay/backups/$(date +\%F).zip" configs storage plugins
```

## Плагины

Плагин — это `.py` файл в каталоге `plugins/` с обязательными полями и списками хуков:

```python
NAME = "Название"
VERSION = "1.0.0"
DESCRIPTION = "Что делает"
CREDITS = "@автор"
UUID = "..."              # валидный UUID4
SETTINGS_PAGE = False
BIND_TO_DELETE = None

def on_new_order(cardinal, event, *args):
    ...

BIND_TO_NEW_ORDER = [on_new_order]
```

Доступные точки подключения: `BIND_TO_PRE_INIT`, `BIND_TO_POST_INIT`, `BIND_TO_PRE_START`, `BIND_TO_POST_START`, `BIND_TO_PRE_STOP`, `BIND_TO_POST_STOP`, `BIND_TO_INIT_MESSAGE`, `BIND_TO_MESSAGES_LIST_CHANGED`, `BIND_TO_LAST_CHAT_MESSAGE_CHANGED`, `BIND_TO_NEW_MESSAGE`, `BIND_TO_INIT_ORDER`, `BIND_TO_ORDERS_LIST_CHANGED`, `BIND_TO_NEW_ORDER`, `BIND_TO_ORDER_STATUS_CHANGED`, `BIND_TO_PRE_DELIVERY`, `BIND_TO_POST_DELIVERY`, `BIND_TO_PRE_LOTS_RAISE`, `BIND_TO_POST_LOTS_RAISE`.

Установка: `/menu` → **Плагины** → **Добавить плагин** → отправить файл. После добавления нужен `/restart`.

> Плагин исполняется с теми же правами, что и бот: он имеет доступ к `golden_key`, токену Telegram и файловой системе сервера. Ставь только тот код, который прочитал сам или получил из источника, которому доверяешь.

## Безопасность

Что стоит сделать сразу после установки:

1. **Ограничь доступ к панели.** `/menu` → **Авторизация** → добавь только свой Telegram ID, включи блокировку входа по паролю (`blockLogin`) после того, как авторизовался сам. Тогда даже знающий пароль не войдёт.
2. **Проверь права на конфиги.** Установщик выставляет `chmod 600` на `configs/_main.cfg`. Проверить: `ls -l ~/4funpay/configs/`.
3. **Не пересылай `backup.zip`** — внутри `golden_key` и токен.
4. **Настрой SSH по ключам** и отключи вход по паролю на сервере.
5. **Смена `golden_key`.** Cookie живёт долго, но истекает при смене пароля на FunPay и при выходе из всех сессий. Новый ключ ставится командой `/golden_key` в Telegram — перезапуск не нужен. При истёкшем ключе бот пишет об этом в Telegram и продолжает попытки, а не падает молча.

Чего в коде нет и быть не должно: отправки `golden_key` или токена куда-либо кроме `funpay.com` и `api.telegram.org`, скрытых каналов управления, телеметрии. Секреты не пишутся в логи ни на одном уровне логирования.

## Что мониторить при изменениях FunPay

FunPay периодически меняет вёрстку и формат AJAX-ответов. Ломается всегда одно и то же — список мест, куда смотреть в первую очередь:

| Что | Где | Признак поломки |
|---|---|---|
| Авторизация, CSRF-токен, ID аккаунта | `FunPayAPI/account.py`, метод `Account.get()` — селекторы `div.user-link-name`, `body[data-app-data]`, `a.menu-item-logout` | при старте сразу `UnauthorizedError` при заведомо живом `golden_key` |
| Баланс и счётчики | там же — `span.badge-balance`, `span.badge-trade`, `span.badge-orders` | баланс `0` или падение при парсинге приветствия |
| Поллинг событий | `FunPayAPI/updater/runner.py`, `Runner.get_updates()` и разбор `orders_counters`, `chat_bookmarks`, `chat_node` | бот запустился, но не видит новых сообщений и заказов |
| Эндпоинт событий | `Account.runner_request()` → `POST funpay.com/runner/`, payload `objects` / `request` / `csrf_token` | ошибки 400/403 в логах на каждой итерации |
| Разбор чата и сообщений | `Account.get_chat()`, селекторы `chat-msg-text`, `chat-img-link`, `chat-msg-author-link` | сообщения приходят пустыми, изображения не определяются |
| Заказы | `Account.get_order()`, `Account.get_sales()` — таблица `tc-item`, поля `tc-date-time`, `tc-status` | нет уведомлений о заказах или неверный статус |
| Лоты и их сохранение | `Account.get_user()`, `Account.save_lot()`, поля формы редактирования лота | автовосстановление и автодеактивация не срабатывают |
| Поднятие лотов | `Account.raise_lots()` → `POST lots/raise` | «не удалось поднять» на всех категориях подряд |
| Отправка сообщений | `Account.send_message()`, `Account.send_image()` | сообщения не доходят до покупателя |

Диагностика: включи полные логи (`logs/log.log` уже пишется на уровне DEBUG) и сравни фактический HTML с ожидаемым селектором. Быстрая проверка живости слоя API — команда `/profile` в Telegram: она дёргает `get_user()` и сразу покажет, парсится ли профиль.

Порядок действий при поломке: откатись на рабочий коммит (см. [Откат](#откат-на-предыдущую-версию)), затем правь селекторы. Логику авторизации и работы с платежами трогай осознанно — ошибка здесь стоит дороже, чем неработающее уведомление.
