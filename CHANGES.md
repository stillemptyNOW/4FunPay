## Новые файлы

### Ядро и инфраструктура

| Файл | Что делает |
|---|---|
| `branding.py` | Единая точка бренда: имя, контакты, имя сервиса, префикс логгера. Плейсхолдеры `{{BOT_NAME}}`, `{{OWNER_TG}}`, `{{REPO_URL}}`, `{{SUPPORT_CHAT}}` подставляются в тексты через `apply()`. Смена названия — правка одного файла. |
| `Utils/secrets.py` | `golden_key` и токен Telegram: приоритет переменных окружения над конфигом, маскирование для логов, предстартовая проверка с указанием, что именно заполнить. Секреты читаются **в момент использования**, а не подставляются в `ConfigParser` — иначе они осели бы в `_main.cfg` при первой же правке настройки из панели. |
| `Utils/backup.py` | Резервное копирование `configs/`, `storage/`, `plugins/`. Логика из `updater.py` сохранена без изменений, вырезана только половина с обновлением из интернета. |
| `Utils/confirmations.py` | Механизм подтверждения критичных действий повторным вводом пароля панели: срок жизни запроса, лимит попыток, привязка к пользователю и чату. **Пока не подключён к `bot.py`** — см. «Что осталось». |
| `NOTICE.md` | Происхождение кода, состояние лицензии апстрима, список поведенческих отличий. |

### Плагины

| Файл | Что делает |
|---|---|
| `plugins/audit_log.py` | Отдельный компактный журнал действий в JSON Lines: заказы, выдача, поднятие лотов. Команды `/audit`, `/audit_export`. Содержимое выданных товаров в журнал **не пишется** — только количество, иначе выгрузка стала бы файлом с ключами. |
| `plugins/watchdog.py` | Heartbeat-файл (его читает `HEALTHCHECK` в Dockerfile) и уведомление в Telegram об аварийных перезапусках с длительностью простоя. При 5+ падениях за сутки предупреждает, что бот падает по кругу. Команда `/health`. |
| `plugins/sales_stats.py` | Своя история продаж, сводки за неделю и месяц с графиками, топ лотов, постоянные покупатели, экспорт в CSV для Excel. Команды `/stats`, `/stats_month`, `/stats_export`. |

### Развёртывание

| Файл | Что делает |
|---|---|
| `install.sh` | Установщик для Ubuntu 22.04/24.04. Python 3.11+ из штатных репозиториев с откатом на deadsnakes, venv, systemd-юнит, `chmod 600` на конфиг. Идемпотентен: повторный запуск не ломает установку. Работает из склонированного репозитория. |
| `4funpay@.service` | `Restart=on-failure` вместо `Restart=always`, `StartLimitBurst=5`, логи в journald, `UMask=0077`, ограничение прав процесса. |
| `Dockerfile`, `docker-compose.yml`, `.dockerignore` | Альтернативный способ развёртывания. Данные в томах, непривилегированный пользователь, healthcheck по heartbeat, лимит памяти и ротация логов. |
| `.gitattributes` | `LF` для `*.sh`, `*.service`, `*.py`, `*.cfg`. Без этого на Linux получаешь `bad interpreter: /bin/bash^M`, а загрузчик конфигов проекта требует LF явно. |
| `.env.example`, `config.example.ini` | Образцы с комментариями на русском по каждому параметру: где взять `golden_key`, где взять токен, что означает каждый переключатель. |

## Что осталось

Честный список того, что не доделано.

### 1. Подтверждение критичных действий не подключено

`Utils/confirmations.py` написан и покрыт тестами, но не вписан в `bot.py`.
Осталось: добавить состояние `CBT.CONFIRM_ACTION`, обработчик ввода пароля и
обернуть в него `act_change_cookie`, `ask_power_off`, `upload_backup`,
`upload_plugin`.

Причина, по которой не сделано сразу: это правка центрального файла панели
управления на ~150 строк, а прогнать её в этой среде не получилось —
зависимости не установились (нет доступа к PyPI). Вписывать вслепую в файл,
от которого зависит весь интерфейс, — плохая идея.

### 2. Рефакторинг структуры (`handlers/`, `services/`, `repositories/`)

Не начат. Сделано частично: типизация и докстринги в новых и переписанных
модулях, `Enum`/`dataclass` вместо магических строк там, где писал с нуля
(`CriticalAction`, `Action`, `WatchdogState`, `Sale`).

Крупная перестройка `tg_bot/` (`bot.py` — 64 КБ, `keyboards.py` — 35 КБ)
осмысленна, но ломает совместимость со сторонними плагинами FPC, которые
импортируют `tg_bot.CBT`, `tg_bot.keyboards` и `cardinal` напрямую. Ты выбрал
«главное чтобы работало хорошо» — поэтому публичные имена я сохранил.

### 3. Проверка селекторов против живого funpay.com

Не выполнена. Код взят с последнего тега апстрима (`v0.1.17.9`, репозиторий
обновлялся в день снятия форка), поэтому селекторы актуальны на этот момент.
Но фактически проверить парсинг можно только с живым `golden_key` на реальном
аккаунте — это шаг 1 и 5 из [TESTING.md](TESTING.md).

Единственная правка в `FunPayAPI` — имя файла исходящих картинок. Логика
авторизации, CSRF, поллинга событий и работы с заказами не тронута.

### 4. Тесты не запускались

Написаны, но не прогонялись: в этой среде нет доступа к PyPI, а `bcrypt`,
`requests`, `pytelegrambotapi` не установлены. Тесты, зависящие от этих
пакетов, помечены `importorskip` — они пропустятся, а не упадут.

Первое, что стоит сделать на сервере:

```bash
pip install -U -r requirements.txt -r requirements-dev.txt
pytest
```

### 5. Плейсхолдеры не заполнены

`branding.py` — `OWNER_TG`, `SUPPORT_CHAT`, `REPO_URL`.
`install.sh` — `REPO_URL`. `README.md` — ссылки на репозиторий.

Пока не заполнены, в интерфейсе видно `{{OWNER_TG}}` — это намеренно, чтобы
не забыть.
