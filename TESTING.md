# Чеклист проверки перед продакшеном

Проходить по порядку. Сначала — на тестовом аккаунте FunPay с дешёвым лотом
(10–20 ₽), и только потом переносить на основной.

**Почему на тестовом.** Ошибка в конфиге автовыдачи означает не «ничего не
произошло», а «покупатель получил чужой ключ» или «заплатил и не получил
ничего». Дешёвый лот на тестовом аккаунте позволяет реально оплатить заказ
со второго аккаунта и посмотреть, что бот сделает.

---

## 0. Автотесты (перед всем остальным)

```bash
pip install -U -r requirements.txt -r requirements-dev.txt
pytest
```

- [ ] Все тесты зелёные.
- [ ] Если что-то пропущено (`SKIPPED`) — значит не установлены зависимости; доустанови и повтори.

Отдельно стоит убедиться, что проходит тест на коллизии — он проверяет, что один ключ не уйдёт двум покупателям:

```bash
pytest tests/test_products_pool.py -v
```

---

## 1. Запуск и авторизация

- [ ] `python main.py` — выводится баннер 4FunPay и версия, **без** упоминаний сторонних проектов и ссылок.
- [ ] В логе строка `golden_key: 0123...cdef` — ключ **замаскирован**, не виден целиком.
- [ ] В логе приветствие: ник аккаунта, ID, баланс, количество активных продаж.
- [ ] Заголовок окна консоли — `4FunPay - <ник> (<id>)`.
- [ ] `configs/_main.cfg` создан, права `600` (`ls -l configs/`).

### Проверка невалидного golden_key

Специально сломай ключ: поменяй в `configs/_main.cfg` последний символ.

- [ ] Бот **не падает** с трейсбеком.
- [ ] В Telegram приходит сообщение «FunPay не принимает golden_key» с пошаговой инструкцией, где взять новый.
- [ ] В логе повторные попытки раз в 30 секунд, а не спам каждые 2 секунды.
- [ ] Верни правильный ключ командой `/golden_key` — приходит уведомление «Подключение к FunPay восстановлено».
- [ ] Сообщение, в котором ты отправил ключ, **удалено из чата** автоматически.

### Проверка неполного конфига

Очисти `golden_key` в конфиге и запусти.

- [ ] Вместо трейсбека — понятный список: что именно не заполнено и где взять.
- [ ] Проверь, что перечислены **все** проблемы сразу (очисти заодно `token`), а не по одной за запуск.

## 2. Панель управления Telegram

- [ ] Бот отвечает на любое сообщение просьбой ввести пароль.
- [ ] Неверный пароль → отказ, **без кнопок и ссылок** (посторонним ничего не показываем).
- [ ] Верный пароль → доступ выдан, в чат приходит уведомление о входе.
- [ ] `/menu` открывает меню настроек.
- [ ] `/profile` — подтягивает актуальные данные аккаунта с FunPay (это же и проверка живости слоя API).
- [ ] `/sys` — загрузка ЦП, ОЗУ, аптайм.
- [ ] `/about` — версия и ссылки **на твои** ресурсы (или без кнопок, если `branding.py` не заполнен).
- [ ] `/logs` — присылает лог-файл.
- [ ] `/update` — выводит инструкцию по `git pull`, **не пытается** ничего скачать.

### Проверка витрины бота

- [ ] Открой профиль своего бота в Telegram: имя и описание **не изменились** после запуска (раньше апстрим перезаписывал их своей рекламой).

### Доступ

- [ ] `/menu` → Авторизация → добавь свой Telegram ID.
- [ ] Включи `blockLogin`. Со второго аккаунта попробуй войти по паролю → **отказ**.
- [ ] Убедись, что сам ты доступ не потерял.

---

## 3. Лоты

- [ ] `/menu` → Автовыдача → лоты подтягиваются с FunPay (список не пустой, названия совпадают с сайтом).
- [ ] Включи `autoRaise` в глобальных переключателях.
- [ ] В логе появляется `Поднял лоты категории <название>`.
- [ ] В Telegram приходит уведомление о поднятии.
- [ ] Повторное поднятие раньше кулдауна FunPay → в логе «Подождите N», бот **не** долбит запросами.

---

## 4. Автоответ

- [ ] `/menu` → Автоответчик → добавь команду, например `!тест` с ответом «Работает».
- [ ] Со второго аккаунта напиши `!тест` в чат продавцу.
- [ ] Ответ пришёл покупателю, в начале — водяной знак из `[Other] watermark`.
- [ ] В Telegram — уведомление о введённой команде.
- [ ] Проверь переменные: ответ с `$username` подставляет ник покупателя.

---

## 5. Автовыдача — главный блок

Создай товарный файл `storage/products/test.txt` с несколькими строками (`test-key-1`, `test-key-2`, …).

- [ ] `/menu` → Автовыдача → привяжи тестовый лот к файлу, в ответе используй `$product`.
- [ ] `/test_lot` → создай одноразовый ключ → отправь команду в чат → товар выдан, из файла **исчезла ровно одна** строка.

### Реальная оплата

Оплати тестовый лот со второго аккаунта.

- [ ] Уведомление о новом заказе в Telegram.
- [ ] Товар пришёл покупателю в чат FunPay.
- [ ] Уведомление о выдаче с указанием остатка товара.
- [ ] Из `storage/products/test.txt` удалена ровно одна строка.
- [ ] Строка, которая ушла покупателю, **не** появилась в файле повторно.

### Пограничные случаи

- [ ] Опустоши товарный файл → оплати заказ → приходит уведомление об ошибке выдачи, бот **не падает**.
- [ ] При включённом `autoDisable` лот снят с продажи после опустошения файла.
- [ ] При включённом `autoRestore` лот вернулся в продажу после оплаты.
- [ ] Купи 2 единицы одного лота при включённом `multiDelivery` → выдано 2 разных ключа.

### Проверка на коллизии вручную

Если хочешь убедиться живьём, а не только тестом: оплати два заказа
одновременно с двух аккаунтов на один лот.

- [ ] Каждый покупатель получил **свой** ключ, дублей нет.
- [ ] В файле стало меньше на 2 строки, не на 1.

## 6. Отзывы и подтверждение заказа

- [ ] Включи `sendReply` в `[OrderConfirm]`. Подтверди заказ покупателем → продавец отправил благодарность.
- [ ] Включи `star5Reply` с текстом. Оставь 5 звёзд → бот ответил на отзыв.
- [ ] Уведомление об отзыве пришло в Telegram.

---

## 7. Ответ из Telegram

- [ ] На уведомлении о новом сообщении нажми «Ответить» → отправь текст → он дошёл до покупателя в FunPay.
- [ ] Кнопка «Больше» показывает историю чата.
- [ ] `/upload_chat_img` → загрузи картинку → отправь её в чат → **проверь у покупателя**, что имя файла нейтральное (`bot_image.png`), без названия сторонних проектов.

## 8. Плагины

- [ ] `/menu` → Плагины → в списке видны «Аудит действий», «Watchdog», «Статистика продаж».
- [ ] `/health` — аптайм, heartbeat «N сек назад», счётчик перезапусков.
- [ ] `/audit` — записи о запуске бота, заказах, выдаче.
- [ ] `/audit_export` — присылает `.jsonl`. **Открой его и убедись**, что там нет выданных ключей и нет golden_key.
- [ ] `/stats` — сводка за неделю с графиком.
- [ ] `/stats_export` — CSV открывается в Excel без диалога импорта, кириллица не побита.

### Проверка watchdog

```bash
# найди PID и убей процесс жёстко, имитируя падение
sudo systemctl status 4funpay@$USER
sudo kill -9 <PID>
```

- [ ] systemd поднял процесс заново (`Restart=on-failure`).
- [ ] В Telegram пришло «Бот перезапущен после аварийного завершения» с длительностью простоя.
- [ ] `/restart` из Telegram → уведомления об аварии **нет** (штатный перезапуск распознан).

---

## 9. Устойчивость на сервере

- [ ] `sudo systemctl restart 4funpay@$USER` → бот поднялся, в Telegram уведомление о запуске.
- [ ] `sudo reboot` → после перезагрузки сервера бот запустился сам.
- [ ] `sudo journalctl -u 4funpay@$USER -f` → логи идут в journald.
- [ ] `grep -ri "golden_key" logs/*.log` → ключа в открытом виде **нет**.
- [ ] `/create_backup` → архив пришёл в Telegram, внутри `configs/`, `storage/`, `plugins/`.
- [ ] Восстановление: удали товарный файл, загрузи бэкап через `/menu` → Конфиги → файл вернулся.

### Проверка секретов в git

```bash
git status --short
git ls-files | grep -E "configs/|storage/|\.env$"
```

- [ ] Вывод второй команды **пустой** — секреты не в репозитории.
- [ ] `git log -p | grep -c "$(grep golden_key configs/_main.cfg | cut -d: -f2 | tr -d ' ')"` → `0`.

## 10. Откат

Отрепетируй заранее, чтобы не разбираться в этом, когда всё сломается.

```bash
sudo systemctl stop 4funpay@$USER
cd ~/4funpay && git log --oneline -5
git checkout <предыдущий_хеш>
~/pyvenv/bin/pip install -U -r requirements.txt
sudo systemctl start 4funpay@$USER
```

- [ ] Бот запустился на предыдущей версии.
- [ ] `git checkout master && git pull` → вернулся на актуальную.

---

## Что проверять после каждого обновления

Короткая версия, на 5 минут:

1. `pytest` — зелёный.
2. Бот запустился, в логе приветствие с ником аккаунта.
3. `/profile` в Telegram отдаёт данные (значит, парсинг FunPay жив).
4. `/test_lot` выдаёт товар.
5. `/health` показывает свежий heartbeat.

Если п. 3 отвалился после того, как FunPay поменял вёрстку — смотри раздел
«Что мониторить при изменениях FunPay» в [README.md](README.md).
